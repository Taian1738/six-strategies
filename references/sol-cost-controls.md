# SOL 低消耗控制

适用协议：`LT-2026-08-21.11`

仅在 SOL 参与时读取。目标是删除重复输入、无关工具调用和冗余输出，而不是降低必要推理、证据质量或审计独立性。

## 一、模型与思考强度

| 场景 | 模型与强度 | 说明 |
|---|---|---|
| 构建任务主控 | `gpt-5.6-sol` `high` | 常规默认；负责路由、整合和风险判断 |
| 复杂/高风险主控 | `gpt-5.6-sol` `xhigh` | 多核心域、公共契约、认证/支付/隐私/迁移/并发/部署等 |
| 关键架构或最终整体审计 | `gpt-5.6-sol` `max` | 不把架构质量换成 token |
| 可独立分解的多域架构 | `gpt-5.6-sol` Codex `ultra` | 多智能体编排；仅有至少两个独立工作流且并行探索确有收益时 |
| 底层架构设计/架构契约审计 | `gpt-5.6-sol` Codex `ultra` | 命中底层架构触发即固定使用；设计者与审计者必须独立 |
| 有界只读事实取证 | `gpt-5.6-luna` `low/medium`；底层为 `max` | 仅 `LUNA_FACT_GATE=PASS`；返回定位事实/冲突/未知，不作语义决定 |
| 低复杂度、低后果且测试充分的实现 | `gpt-5.6-luna` `low` | 由契约约束输出和写入范围 |
| 非平凡语义或测试薄弱的实现 | `gpt-5.6-luna` `medium` | 不用失败次数代替事前风险判断 |
| 有界高后果或复杂实现 | `gpt-5.6-luna` `high` | 仅 `LUNA_GATE=PASS`；认证接线、迁移步骤、并发实现、复杂算法等；随后独立 SOL 审计 |
| 底层有界搭建/返修/确定性门执行 | `gpt-5.6-luna` `max` | 仅 `LUNA_GATE=PASS`；架构门后执行冻结契约，无选择权 |
| 能力门失败且无法继续冻结的关键实现 | 独立实现 `gpt-5.6-sol` `max` | 只完成最小不可分切片；不得兼任设计者或审计者 |

不得自动选择或回退到 Terra。主控只用 `high/xhigh`。普通关键架构和不可分关键实现的 SOL `max` 是最高单代理 effort；不要为了省钱统一降到 `xhigh`。Codex `ultra` 是多智能体编排而非原始 API effort：普通架构只有可真实并行分解时才使用，底层架构设计和架构契约审计固定使用；原始 Responses API 使用模型 `max` + Multi-agent beta，不得发送 `reasoning.effort="ultra"`。

派发前按 `SKILL.md` 预检模型、模式、effort、工具和独立性，只允许 `AVAILABLE`、严格定义的普通 `DEGRADED` 或 `SOL_ABSORBED` 继续。依次判断合法自动路径、需批准的具体可用替代、无合法替代的必需能力缺失，分别写相应状态；底层必需能力缺失固定 `BLOCKED_MODEL`，不与 `NEEDS_USER` 并列。禁止“最强非 Terra”“成本最低且胜任”等未预检回退。

## 二、最小充分上下文

SOL 输入按固定顺序提供：角色和输出契约、`R-/可选 A-/F-/T-` 需求映射、稳定接口/不变量、精确路径和符号、当前 diff、失败证据、必要外部证据。未变化的稳定指令保持相同前缀和顺序，以便运行环境支持时利用缓存。

- 先由主控直接生成，或让通过 `LUNA_FACT_GATE` 的 Luna 抄录模块入口、精确调用边、变更文件清单和测试原始结果；模块边界、风险及其他语义摘要由主控/SOL形成，SOL 再按需打开具体文件。
- 用路径、符号、diff 和原始失败行代替完整文件、完整日志、完整对话和全仓库树。
- 已通过且未受影响的阶段只给结论与证据位置，不重新叙述。
- 输入接近超长上下文前，由主控/Luna 按功能拆分并保留接口、失败路径和来源；不要无来源地概括关键事实。上下文大小是软警戒，不得截断完成正确设计所需的信息。
- 不要求 SOL 输出隐藏思维过程、推理摘要、教程或实现代码；只要可执行的契约、决策、问题和验证。

### SOL 生命周期与缓存

- 普通交付生命周期在首次 SOL 委派前登记回合预算：架构 `N=0/1`，只有可证明互不依赖的关键架构工作流才取 `2≤N≤6`；严格例外中途审计 `0/1`；适用的最终整体审计 `0/1`；集中返修后的复审 `0/1`。普通任务最多 **4** 个委派 SOL 回合，独立架构特例最多 `N+3≤9`；这是上限而非配额，组件、功能、文件或维度数量不得增加预算。超出只能因新出现且会改变安全交付结论的重大证据，由主控说明已有预算为何无法处理并取得用户明确同意。
- 底层架构单独登记架构设计、架构契约审计、实现审计和后续统一复审回合；每个新建审计回合计数并记录模型、输入证据和结果，但不套用普通任务四回合或独立架构 `N+3` 上限。存在 [foundation-gate.md](foundation-gate.md) 定义的客观进展时继续；首个完整无进展轮只允许一次最终收敛尝试，连续第二个无进展轮立即 BLOCKED。不得因普通预算提前停止或伪造 PASS。
- 底层任务仅在缺少用户授权/产品决定、缺少改变结论的外部事实、必要工具证据不可得、必需模型/执行模式/审计独立性不可用、并发写入破坏且无法稳定恢复任务指纹、同一修复方案连续两次失败且无改变结论的新证据，或连续两轮无客观进展时标记 BLOCKED；解除阻塞后从确定性门重新开始。
- 每次新建 SOL 并触发其工作回合计 1 次；向既有 SOL 使用会触发新工作回合的 `followup_task` 或等价操作也计 1 次。被动接收返回、查询状态或发送不触发新回合的消息不计。预算耗尽后不得靠复用旧代理绕过计数。
- Luna 与 SOL 各有最多 6 个同时活跃槽位；这是独立的滑动并发容量而非累计调用数，实际仍受环境全局并发限制。架构 SOL 完成当前成批问题后即交付决策增量；不得提前创建终审 SOL，也不得让委派 SOL 在 Luna 实现、人工等待或外部等待期间空置。只有登记为互不依赖的关键架构工作流才并发多个 SOL；终审和复审各始终一个。
- 创建 SOL 前先收齐本阶段会共同影响决定的问题、路径、diff 和验证结果，一次询问；不要把可合并的问题拆成多次短调用，也不要按组件或同一角色并开重复 SOL。
- 同一角色的紧邻增量优先发回原 SOL，仅发送新增/替换/撤销的 `R-/A-`、相关 diff 和新证据。若已经长时间停顿、发生上下文压缩、实现阶段跨度很大，或运行环境未暴露缓存命中状态，则按“无缓存折扣”估算成本；比较后选择“复用旧代理的新增输入”与“无历史新代理的最小任务包”中总输入更小者。
- 不为追求缓存命中重发旧对话、完整仓库、完整计划或完整日志。稳定系统约束保持固定前缀，易变证据放在末尾；项目决策及时写入索引和 `A-` 增量，让后续新任务只读精确记录。
- 最终审计必须独立，但只在变更集冻结、测试结果齐备后即时创建；审完即结束。不得在架构阶段预留或“养着”审计 SOL。
- 缓存命中和有效期不可见时，不把缓存优惠当作预算依据。任何调用即使全部按直接输入计费，也应保持经济；缓存只视为额外收益。
- 跨日、长时间暂停、上下文压缩/恢复、任务移交或已知 skill 更新后，在任何新 SOL 回合前重读当前 `SKILL.md`、本文件及该阶段引用的 `dispatch-contracts.md`/`audit-routing.md`，核对最新协议版本和已用/剩余预算；不得只凭压缩记忆续派。

默认保持 Codex 当前模型窗口和自动压缩值，不全局启用扩展窗口。先通过项目索引、重大改动日志、精确路径、功能拆分和有来源压缩控制上下文；只有这些手段仍会丢失关键接口、失败路径或证据时才为单次任务使用扩展窗口，并在启用前核实当前模型目录、长上下文计费阈值和实际输入规模。窗口容量不是必须填满的预算。

## 三、MCP 与外部证据

SOL 的默认 MCP/联网预算为 **0**。本地搜索、项目文件、既有证据和验证结果足够时，禁止为了“再确认一下”调用网页、桌面控制、图像、连接器或宽泛枚举工具。

确有会改变架构或审计结论的外部未知事实时，SOL 先返回：

```text
NEED_EXTERNAL_EVIDENCE
决定：A-...
缺失事实：...
为什么会改变决定：...
首选权威来源：...
最小查询：...
```

主控直接收集，或把限定来源的机械抄录交给通过 `LUNA_FACT_GATE` 的 Luna，再由主控压缩为：

```text
E-编号：E-...
事实：...
来源：URL、资源 ID 或本地路径
版本/获取时间与精确章节、字段或定位：...
最小充分原文或结构化原始响应：...
全部已知限定、适用范围与冲突：...
置信度：...
影响决定：A-...
```

### 软预算

- 普通外部事实以 1 次精确查询加 1 次精确读取为目标；瞬时失败最多重试一次。
- 预算不是硬上限。来源冲突、版本不明、安全/法律/兼容性事实易变，或少一次调用可能改变关键决定时，可以增加调用，但任务包必须记录“影响哪个决定、为什么现有证据不足”。
- 关键事实由主控 `high/xhigh` 提取。若限定条件仍可能被摘要遗漏，允许 SOL 对已定位的权威来源做一次定向原文读取，不得扩展为漫游搜索。
- 同一决定经过两轮定向补证仍不足时，返回 `UNRESOLVED_EXTERNAL_FACT`，并给出保守方案、需要用户决定的选项或明确阻塞；不进入无限补证循环。
- 优先项目内事实、工具原生结构化接口和官方一手来源。先筛选 ID，再读取命中的具体对象；设置服务端过滤、字段、日期、数量和分页上限。
- 禁止无目标的 `list all`、重复同一搜索、读取整个知识库/邮箱/网盘、逐页浏览或把大量原始结果转交 SOL。
- 视觉任务才使用截图、计算机控制或图像工具。可由确定性脚本/命令完成的过滤、聚合和格式转换，不交给 SOL 逐条处理。
- 最终审计复用已收集的 E-证据；仅当证据已过期、相互冲突或 diff 引入新的外部依赖时刷新。

当前运行环境若不能硬限制代理工具列表或调用次数，上述预算作为任务契约执行。若以后支持工具白名单、延迟加载或 Tool Search，只暴露本任务所需工具；若支持可验证的程序化工具调用，仅用于确定性筛选/聚合，不用于语义判断、授权、引文选择或真实外部状态变更。

## 四、输出与复用

### 架构输出

只输出：目标/非目标、模块边界与数据流、公共接口与不变量、失败路径、安全边界、已知扩展缝、`R- →（A- 可选）→ F- → T-` 覆盖、取舍/风险、需要用户决定的事项。删除通用最佳实践、重复需求、逐文件教程、样板代码和未被需求支持的未来设计。不得设置会截断这些内容的硬字数上限。

同一项目的架构增量只有在时间紧邻、上下文未压缩且复用的预计总输入更小时才发回原架构代理；仅传变化的需求、相关契约、diff 和失败证据，并只返回新增/替换/撤销的 `A-` 决策。否则以已落盘的 `A-` 决策和最小证据包新建无历史任务。最终整体审计必须使用独立 SOL，不能以节省 token 为由让设计者自我终审。

### 审计输出

普通任务按 [audit-routing.md](audit-routing.md) 在最终变更集和全部证据冻结后创建一个独立 SOL 终审，完成五项核心维度及被触发专项；全部问题集中修复后只用一个 SOL 回合统一复审所有未关闭编号及合并影响面。所有维度共用同一最小证据包，不复制上下文或按维度、功能、文件、专项工具启动审计代理；未触发专项只给一行“不适用”依据。先审 diff、需求映射、维度触发表和验证结果，再按需读取具体实现。通过时只返回总判定、核心状态、专项状态和验证证据；不通过时只返回有证据且不重复的问题。

底层架构按 [foundation-gate.md](foundation-gate.md) 由同一独立审计角色的 SOL Codex `ultra` 统一覆盖强制矩阵；每轮输出矩阵逐项状态、阶段化证据、确定性门、稳定指纹和累计回合数。代理可按缓存/压缩规则重建，但必须继承 append-only 回合账本、同一报告、矩阵和全部问题 ID，禁止删除、重编号或重置。FAIL 时输出 [dispatch-contracts.md](dispatch-contracts.md#sol-审计修复契约) 的完整修复契约、执行者和能力门证据；架构门的机械文档修订由 Luna `max` 执行，架构决定/契约修订由原设计 SOL Codex `ultra` 执行；实现门中，通过能力门的有界批次由 Luna `max` 执行，其余最小不可分关键切片由独立实现 SOL `max` 执行。重跑确定性门、重冻结后继续完整统一审计。PASS 仅在原始需求到 `R-` 完整、全部适用维度有阶段匹配的定位/命令证据并 PASS、无 UNKNOWN、确认问题全关闭、确定性检查通过且指纹稳定时成立；否则保持 FAIL 或真实 BLOCKED。

## 五、项目记忆与缓存

- 全局模型/MCP/成本策略只保存在本 skill；项目只记录偏离默认策略的例外。
- 复用的外部事实保存 E-编号、官方来源、版本/时间、精确定位、最小充分原文/结构化响应、全部已知限定、影响决定和失效条件。
- 易变、冲突、法律、安全、价格或版本事实到期后重新核实；不要缓存敏感数据或无关原文。
- 项目索引用 `R-/可选 A-/F-/T-` 和路径/符号导航，不复制代码与历史聊天。
- 重大改动日志只保存集成级差异和验证依据；SOL 只读取与当前功能、符号、公共契约或数据结构匹配的日志，不加载全部历史。

## 六、不得为节省消耗而做的事

- 不统一降低关键架构与最终整体审计的推理强度。
- 不设置无法因质量风险突破的 MCP 硬上限。
- 不截断必要架构章节或关键原始证据。
- 不让无来源的二次摘要代替公共接口、安全边界、错误路径和兼容性事实。
- 不让同一代理兼任架构设计和最终整体审计。
- 不因省 token 跳过用户验收、回归测试、数据安全或权限验证。
