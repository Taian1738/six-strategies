# 最小代理任务包

适用协议：`LT-2026-08-21.11`

仅在确实需要 SOL/Luna 委派时读取。代理共享文件系统，因此优先发送路径和符号，让代理自行读取指定文件；不要复制完整对话、仓库内容或全部项目文档。

任务启动以及跨日、长暂停、上下文压缩/恢复、移交或已知 skill 更新后的首次派发前，重读当前 `SKILL.md` 与本文件。任务包版本不同于当前协议时停止派发并回报主控；已运行任务不被强退，待安全结束后按新协议重排后续队列。

## 通用任务包

```text
协议版本：LT-2026-08-21.11
角色与模型：<SOL 架构/审计、Luna 事实取证、Luna 实现 或 Luna 日志>；架构/编码/修复/代码审查应用 Ponytail full，纯事实取证/日志只做单一来源的最短充分记录且不加载 Ponytail
执行模式与可用性：<single_agent + effort | codex_ultra | responses_multi_agent_beta>；<AVAILABLE/DEGRADED/BLOCKED_MODEL/NEEDS_USER/SOL_ABSORBED>
能力门：<LUNA_FACT_GATE=PASS | LUNA_GATE=PASS | N/A；附逐项证据位置>
GUI/万相路由：<WANXIANG_ROUTE=ON|OFF|N/A + 触发证据；无 GUI 工作才可 N/A；ON 时列当前角色需执行的万相阶段与已冻结 GUI 契约位置，OFF 时禁止隐式套用>
目标：<一句话，可观察>
验收：<最多数项，可执行检查>
需求映射：<相关 R-/可选 A-/F-/T-；琐碎任务可省略>
读取：<精确文件、目录、符号或当前 diff>
允许修改：<精确文件集合；只读任务写“无”>
禁止修改：<共享或用户改动文件>
外部权限：<允许的网络、项目外写入或外部状态操作；没有则写“无”>
外部证据：<E-编号、事实、来源/版本/时间、关键原始字段；没有则写“无”>
MCP 预算：<SOL 默认 0；确需补证时写软预算和决定影响>
既有契约：<仅列本任务必须保持的接口/数据不变量>
验证：<命令或可重复步骤>
约束：普通代理禁止继续委派；仅 `codex_ultra`/`responses_multi_agent_beta` 顶层编排者可创建已授权内部工作者，内部工作者不得再委派且必须计入并发池；禁止未授权外部操作、破坏性操作及清理用户改动
返回：状态、修改文件、验证结果、必要决策、剩余风险；不要长篇复述
```

普通 SOL 单代理调用默认使用 `fork_turns: "none"`、`model: "gpt-5.6-sol"`、`reasoning_effort: "max"`；只有普通架构可明确拆成至少两个独立工作流时才使用 Codex `ultra`。底层架构设计和独立架构契约审计固定使用 `gpt-5.6-sol` + Codex `ultra`。`ultra` 不是原始 Responses API 的 `reasoning.effort`；API 路线必须写所选模型的 `max` 和 `responses_multi_agent_beta`，若收到 `reasoning.effort="ultra"` 则以 `BLOCKED_MODEL` 拒绝调用并要求修正。每个 `ultra` 是一个顶层编排任务，内部工作者按实际模型计入对应滑动池和环境全局槽位；统一审计的内部工作者仅提供证据，由顶层审计任务形成唯一总判定和修复契约。普通只读事实取证先通过 `LUNA_FACT_GATE` 后使用 Luna `low/medium`，底层可实施性取证固定 Luna `max`；任何语义决定转主控/SOL。普通 Luna 实现、返修和跨模块日志在 `LUNA_GATE=PASS` 后按 low/medium/high 分级，底层有界搭建、返修和确定性门使用 Luna `max`；能力门失败且不能继续冻结的最小不可分关键切片使用与设计者/审计者分离的实现 SOL `max`，但该路线不得替代不可用的 Luna 模型或必需执行模式。模型和能力按 `SKILL.md` 的可用性状态执行，不使用定性回退或自动 Terra。新建调用使用无历史任务并补齐最小上下文；仅在时间紧邻、上下文未压缩且总输入更小时，允许按下文规则用 `followup_task` 复用原架构代理。任务包无法明确允许写入文件时，代理只读分析并返回主控。

SOL 的上下文、MCP 和输出约束遵守 [sol-cost-controls.md](sol-cost-controls.md)。稳定指令放在任务包前部，任务特有的路径、diff 和证据放在后部；保持字段和文件顺序稳定，避免把完整聊天或已验证的旧结果反复发送。

## Luna 事实取证包

仅用于 `LUNA_FACT_GATE=PASS` 的严格只读事实收集；不能用于架构设计、风险判定、审计、日志归纳、实现或返修。普通任务按范围和机械分支量使用 Luna `low/medium`，底层架构可实施性取证使用 Luna `max`。除通用任务包外必须提供：

```text
待回答事实：<逐项列出只需抄录即可回答的问题；不得要求结论、建议或优先级>
读取白名单：<精确路径、符号、字段、diff；禁止自行扩大>
允许只读命令：<rg、查看、只读测试/查询的精确命令；没有则写“无”>
禁止行为：修改/生成文件、安装依赖、启动后台服务、改变外部状态、归纳架构/安全/长程状态、给修复方案或 PASS/FAIL
LUNA_FACT_GATE=PASS：
  1. 范围有界：<路径/符号/命令足以回答>
  2. 输出受限：<仅 FACT/CONFLICT/UNKNOWN 和原始定位>
  3. 无语义决定：<不要求产品/架构/API/安全/状态推导>
  4. 无副作用：<写集为无；命令均只读>
  5. 可核验：<每条事实必须返回 path:symbol/line 或命令及关键原始结果>
停止条件：需要白名单外文件、跨模块语义归纳、信任边界/权限判断、长程状态推理、写入或外部副作用时立即停止，只返回已取得证据和缺口
返回：
  FACT <编号>：<原样事实>；来源=<path:symbol/line 或命令+关键结果>
  CONFLICT <编号>：<相互冲突事实及各自来源>
  UNKNOWN <编号>：<缺失内容、已查范围、停止原因>
```

主控或设计 SOL 必须逐项核对后才能形成契约、风险或修复决定；不得把 `FACT` 标签本身当作真值证明。事实包结束后释放 Luna 槽位，后续写入另行通过 `LUNA_GATE`。

## SOL 架构包

只用于新项目关键架构或跨模块高风险设计。要求输出：

1. 最小可行模块边界和数据流。
2. 需要冻结的公共接口与不变量。
3. 框架/依赖选择及一条决定性理由。
4. 失败路径、安全边界和用户已知需求对应的扩展缝。
5. `R- → A- → F- → T-` 覆盖关系，以及按文件所有权划分的实现批次、每批 `LUNA_GATE` 五项证据、唯一执行者和验证路径。
6. 明确非目标、风险、取舍与需要用户决定的事项。
7. `WANXIANG_ROUTE=ON` 时，直接按当前 `$wanxiang` 产出并冻结 GUI 宿主映射、风格契约、组件/状态/输入/无障碍/平台不变量和分阶段验证；`OFF` 时只保留现有视觉体系，不另做 UI 方案；`N/A` 时确认本任务无 GUI 工作并省略 GUI 契约。
8. 建立或重构应用/运行时底座时，按 [foundation-gate.md](foundation-gate.md#应用架构最小闭包) 输出 `AC-0` 至 `AC-8` 闭包账本：基线/范围指纹、最小性准入、拓扑与 owner、权威状态/契约层级、边界/载体、组合/注册、generation 生命周期、切换/健康/恢复、真实发布物闭包及其确定性 gate；逐项给精确 `path:symbol` 或可执行验证，不适用项给非触发证据。

禁止输出通用教程、未被当前功能需要的扩展层、整套样板代码或内部思维过程。架构契约可短，但不得为了省 token 省略上述必要章节或 Luna 真正实施所需的路径、符号、步骤和边界。

在同一次架构调用结束前自检需求覆盖、接口一致性、失败路径、稳定性和真实需要的扩展缝；发现矛盾直接修正后再返回，不为架构另开审计代理。

SOL 产出实现批次、或主控把 SOL 契约转成任务时，必须为每个 Luna 提供下面的可执行实现包；缺少会影响行为或文件所有权的字段时禁止派发：

```text
唯一已决方案：<一个确定方案；不得给备选或把决定留给 Luna>
功能行为：<用户可观察的正常、失败与恢复流程；明确边界情况和非目标>
具体实现：<按依赖顺序逐文件、逐符号列出修改；含入口/调用者、复用点及连接方式>
接口签名/schema 前后值：<完整签名、类型、字段、事件或协议变化；无变化也明确写出>
算法/伪代码：<分支、循环、状态转换、并发顺序和关键不变量；机械任务写“无需算法”>
状态/错误/cleanup：<输入/输出、状态转换、错误传播/回退、所有权、释放和恢复时序>
应用架构闭包落点：<底层应用任务逐项列 AC-0..AC-8 对应 owner、权威来源、契约层级、载体、generation、提交/回滚和 path:symbol/T-；非此类任务写 N/A>
AC-7 产物证据：<触发时按适用性子表列真实 artifact 路径/identity/digest、物理闭包与 license/notice、clean-environment 探针、升级/卸载/回滚矩阵、签名/publisher/发布清单及所有入口 gate parity；每个不适用子项给证据；未触发写 N/A>
GUI/万相契约：<ON 时逐屏/组件写明已冻结的布局、语义 token、默认/悬停/焦点/激活/选中/禁用/加载/空/错误/破坏性/溢出/减弱动画状态、输入矩阵、无障碍与视觉验收；OFF 时写“沿用现有设计系统，禁止换肤/重做布局”，并列允许的最小 UI 行为改动；N/A 时写“无 GUI 工作”，不得新增 UI 写集>
写入所有权：<独占允许修改文件；禁止修改的共享/用户文件；可调用但不可改的接口>
依赖与就绪：<前置 F-/A-、已冻结契约、隔离资源；未满足则不启动>
风险强度：<语义复杂度、后果风险、测试充分度及 Luna low/medium/high/max；底层固定 max>
LUNA_GATE=PASS：<逐项提供上下文有界、决定冻结、信任边界冻结、长程状态枚举、验证无关键 UNKNOWN 的证据；任一项缺失即不得派发>
验证：<与验收逐项对应的测试用例、失败注入、精确断言、命令和成功判据>
回滚：<精确撤销步骤、数据/配置回滚及不可回滚边界>
停止条件：<契约缺失/冲突、写集扩大、共享状态未隔离、实际代码与说明矛盾时，在写入前停止并回报缺失事实>
```

“精简”只删除无关历史、重复叙述和完整文件粘贴；不得只写“实现 F-xx/按现有模式处理”，不得把产品行为、架构、接口、算法、失败路径或错误语义留给 Luna 猜测。Luna 无需复述计划，也不得在多个方向间选择；任务包完整时直接实施，触发停止条件时只返回精确差异与证据。

## SOL 审计修复契约

底层架构或普通审计判定 FAIL 时，审计 SOL 必须先按根因合并相互冲突的问题，交付唯一、无备选、实现完整的修复契约；主控不得摘要、弱化或改写为开放式建议。每项问题或合并批次使用以下模板，缺一字段不得派发任何执行者：

```text
协议版本：LT-2026-08-21.11
问题/批次编号：AR-...
唯一执行者：<架构门：Luna max 或 原设计 SOL Codex ultra；普通任务/实现门：Luna low/medium/high/max 或 与设计者/审计者分离的实现 SOL max>
执行者能力门证据：<Luna 时逐项证明 LUNA_GATE=PASS；原设计 SOL 时写明需修订的架构决定/契约及为何不是机械文档改动；实现 SOL 时写明哪一项失败、为何无法继续冻结及最小不可分边界>
确认根因和触发证据：<可复现触发条件、原始命令/结果、精确定位>
唯一修复决定：<一个确定方案；禁止备选方案>
精确 path:symbol：<每个受影响文件、符号、行或配置键>
接口签名/schema 前：<完整旧签名或 schema；无变化写明无变化>
接口签名/schema 后：<完整新签名或 schema；无变化写明无变化>
逐步逐文件改法：<按依赖顺序逐文件、逐符号说明具体写入>
算法/伪代码：<状态、分支、循环、关键不变量的可执行算法>
状态/并发/错误/cleanup 时序：<事件顺序、锁/所有权、错误传播、回滚和资源释放>
应用架构闭包修复：<若命中 AC-0..AC-8，逐项写精确 owner/权威来源/契约层级/载体/generation/提交与回滚的前后值及确定性 gate；否则写 N/A>
AC-7 产物修复：<触发时按适用性子表写真实 artifact、identity/digest、物理闭包与 license/notice、clean-environment 生命周期探针、签名/publisher/发布清单、入口 gate parity 的前后值和命令；每个不适用子项给证据；未触发写 N/A>
依赖顺序：<前置契约、先后批次、可并行边界和整合点>
测试用例与精确断言/命令：<每个触发路径、失败注入、恢复路径、断言和可复制命令>
禁止改动：<文件、符号、接口、行为和范围外状态>
成功判据：<可观察结果、确定性检查结果、接口/矩阵状态和指纹条件>
回滚：<精确撤销步骤、数据/配置回滚和不可回滚边界>
冲突停止条件：<契约与真实代码/其他契约不一致、写集扩大、指纹变化或证据缺失时写入前停止并回报>
```

模板不得使用“考虑”“检查”“按现有模式”“自行决定”或“A 或 B”来代替动作、选择、位置、断言或判据。Luna 没有产品、架构、接口或算法选择权；真实代码与契约冲突时必须在写入前停止并回报差异。架构门 FAIL 时，机械文档修订才允许 Luna `max`，涉及架构决定或契约语义的修订返回原设计 SOL Codex `ultra`；普通任务/实现门的能力门失败不得靠提高 Luna effort 绕过，必须先由 SOL 冻结缺口或改派独立实现 SOL。审计 SOL 必须一次消解冲突并按确认根因合并批次，不得把一个根因拆成多个维度或组件修复任务，也不得亲自执行修复。

### 分模型滑动并发池

- Luna 与 SOL 各自最多 **6 个同时活跃子代理**；分别取 `min(6, 对应模型池可用槽位, 运行时剩余总槽位)`。两个池彼此独立，但仍共同受包括主控在内的环境全局并发限制；环境只剩 3 个槽位时不能声称同时运行 6+6。
- 6 是滑动并发上限，不是单批或生命周期累计数。只有当前回合正在采样、调用工具或执行任务的代理计为活跃；代理完成、返回当前回合或停止工作即释放槽位，可立即创建或唤醒下一个就绪代理，因此历史创建总数可以超过 6。
- SOL 池只并发真正独立的关键架构/推理工作流；正式整体终审与集中复审各固定为一个 SOL，不按组件、文件、维度或专项拆分。池有空位不构成创建 SOL 的理由。
- 架构前，主控只把分别通过 `LUNA_FACT_GATE` 的不同模块或问题只读调查放入就绪队列并行取证；Luna 不形成契约或风险结论，写入开始前由主控/SOL核对事实并冻结公共契约和文件所有权。立即派发全部安全且实质的已就绪批次直到有效上限；任一任务结束后立即补入下一个已就绪批次，不等待同一批其余任务。
- 优先并发：按不同模块/问题划分的只读入口与调用链定位、写入集合独占的实现、使用隔离资源的测试与构建检查、互不依赖的证据整理。只读任务不得重复扫描同一区域来回答同一问题。
- 不并发：同一文件或公共类型、清单、路由、注册表、迁移、锁文件；同一 Git 索引、生成目录、缓存、数据库、端口、服务、后台进程或真实外部状态；契约未决或依赖未满足的任务。能可靠隔离时使用独立工作树/临时目录/端口，否则串行。
- 共享入口和最终集成只由主控或一个指定整合者写入。每个 Luna 先完成自己的局部验证并返回结构化结果；整合者再做跨批次回归，避免多人抢修合并冲突。
- 共享上下文且改动很小的工作合并为一个批次；不得只为凑满 6 个而切碎任务。若并发导致 CPU、内存或 I/O 争用并拉长总耗时，主动降低有效并发数。
- 单个批次失败或等待时，不阻塞与它无依赖的就绪批次；主控继续补槽，并单独处理失败任务。普通代理不得自行嵌套委派；只有任务包明确标记的 `codex_ultra`/`responses_multi_agent_beta` 顶层编排者可创建内部工作者，且内部工作者不得再委派。

## SOL 审计包

读取并遵守 [audit-routing.md](audit-routing.md)。普通任务正式终审在变更集与全部适用证据冻结后创建一次，集中修复后统一复审一次；底层架构按 [foundation-gate.md](foundation-gate.md) 在架构门及实现门中重复完整统一审计直到 PASS 或 BLOCKED。两种任务都使用独立于设计者和实现者的一个统一审计 SOL，不按维度、功能、文件或专项工具拆分代理；只有用户已运行且完整满足对应审计契约的原生 `/review` 才可直接替代。

输入必须包含：全部规范化 `R-` 验收语句与明确非目标、需求覆盖表、架构契约、命中的项目日志、测试结果、维度触发表，以及每个返修批次的执行者/Luna 能力门证据。`WANXIANG_ROUTE=ON` 时再提供触发证据、冻结的万相 GUI 契约、实现路径和最新运行/视觉/输入/无障碍验证；`OFF` 时只提供现有设计约束与实际受影响 UI 行为，不扩展为视觉重审；`N/A` 时提供无 GUI 工作的范围证据且不展开体验专项。Git 仓库再提供基准提交/版本、完整 `git status --short`、任务范围 staged/unstaged/untracked 变更、无关用户变更排除清单和任务文件指纹；无 Git 项目提供任务范围文件清单/哈希及可用的前后证据，不强制初始化仓库。按触发项补充性能、兼容迁移、运维、体验、依赖平台或交付证据。安全维度按 [audit-routing.md](audit-routing.md) 的触发表低优先级展开；若申请额外安全工具，任务包必须列出具体信任边界、精确输入/数据 `path:symbol`、现有测试缺失的明确断言、仅限这些路径的允许检查/命令及其会改变的交付判定。字段不全不得调用工具；第三方插件或全域扫描只有用户明确点名插件和精确范围时才允许。

返回格式：

```text
结论：通过 | 不通过 | 证据不足
核心：缺陷=<通过/不通过/未知>；功能=<...>；验证=<...>；性能资源=<...>；架构集成=<...>
专项：<名称=通过/不通过/未知/不适用: 一行依据>
问题：按阻断/高/中/低排序；每项包含维度、文件与位置、触发条件、影响、最小修复指令、验证方法
证据：运行过的命令及结果
修复契约：<结论为不通过时，对普通和底层任务均附本文件“SOL 审计修复契约”的全部字段；通过时写无>
```

审计者对产品文件只读，唯一允许写入的是预定审计报告和 FAIL 时附带的完整修复契约。没有问题时仅返回总判定、核心状态、专项触发表和验证证据。报告写入 `audit-routing.md` 指定的位置；对话不重复报告全文。不要提出风格偏好、无测量的性能建议、推测性架构重构或当前范围外的优化。同一问题不得跨维度重复。普通返修时先汇总全部确认问题给实现者集中处理，再把所有未解决编号、相关路径和合并验证证据作为一个任务统一复审；普通任务自动返修后只允许这一次 SOL 复审。底层任务按 [foundation-gate.md](foundation-gate.md) 继续同一审计角色的完整统一审计；只要有可执行进展就继续，直到 PASS 或真实 BLOCKED。

架构变化仅在时间紧邻、上下文未压缩且预计总输入更小时用 `followup_task` 发给原架构代理；只发送变更需求、相关契约、diff 和新证据，并只返回 `A-` 决策增量。长时间停顿、缓存状态未知或旧历史明显大于最小任务包时，新建无历史架构任务并读取已落盘的 `A-` 决策。终审不能复用架构代理，以免降低独立性。

## Luna 日志包

只在重大改动已经实现并完成验证、适用终审通过、相关代码与当前状态索引写入者全部结束后调用；无需终审的改动在验证后调用。开始前冻结基准版本、任务范围产品文件/当前状态索引指纹、完整工作树状态和明确排除的无关用户变更；预定日志文件、日志索引、审计报告及缺失时补入的通用日志入口不计入产品指纹。日志任务不得与任何相关写入并行。仅单模块、无公共接口/数据/迁移语义变化且字段可直接从证据抄录时使用 Luna `low`；涉及多个模块、公共契约、数据流、迁移/恢复或需归纳 `A-` 决定时，任务包必须先以冻结证据通过 `LUNA_GATE` 再使用至少 `medium`。能力门失败时由主控补齐冻结证据，不把全仓归纳交给 Luna。Luna 不重新设计架构，不从聊天猜测事实。

除通用任务包外提供：基准版本、任务范围完整变更文件清单/指纹、无关变更排除清单、相关 `R-/A-/F-/T-`、架构决定增量、公共接口/数据/配置变化、迁移或回滚步骤、验证/审计结果和现存风险。允许写入的文件仅限本次 `C-` 日志、`docs/ai/changes/index.md` 和确需更新的项目索引行。

要求：

1. 一个集成级改动只写一份日志，不按代理、提交或文件拆分。
2. 只记录可由代码、配置、diff 或验证证实的事实；证据不足时停止并返回缺失字段。
3. 不粘贴源码、原始 diff、完整测试输出、聊天内容或通用说明。
4. 更新日志索引，但不把全部日志标题复制进 `必读.md`。
5. 写后重新核对产品文件和当前状态索引指纹，并确认除预先允许的日志/审计元数据外没有新增写入；只有产品范围发生变化才返回“变更集已移动”。日志任务自身的合法写入不得触发重跑。
6. 返回日志路径、索引行、覆盖的 `R-/F-`、验证证据和仍未知事项，供主控核对。
