# 项目记忆

适用协议：`LT-2026-08-21.11`

仅在新项目、多功能项目或预计会持续修改时读取并应用本文件。目标是让后续代理先读一个短索引，再按功能加载少量文件，而不是重新探索整个仓库。

## 复用优先

先查找仓库已有的项目地图、架构说明、功能索引或贡献指南。能承载同等信息时直接增量更新，不再创建第二套事实来源。只有没有等价索引时才采用下面的默认布局。

## 默认文件布局

```text
必读.md
docs/ai/features/
  F-001-功能名.md
  F-002-功能名.md
docs/ai/changes/
  index.md
  C-YYYYMMDD-01-简名.md
```

简单项目只需 `必读.md`。只有功能的接口、数据流、约束或文件映射无法在索引表中说清时，才创建对应的功能文档。`docs/ai/changes/` 只在第一次重大改动时创建。不要创建空目录、占位文档、README、完整源码副本或逐文件解说。没有任何索引且本次只是琐碎修改时，用搜索定位并跳过建档。

- 只保留当前仍存在、会影响下一次修改的风险。

`必读.md` 是路由器，不是设计论文。保持首次阅读所需的最小信息；表格或章节开始变得难以扫描时，把条件性细节移入功能文档。`A-` 表只保存以后修改仍需知道的决定、理由和重新评估条件；临时实现选择不落盘。稳定约束若已由某个 `A-` 完整表达，只引用该 ID，不重复正文。

重大改动日志是历史依据，不是当前状态的第二份副本。当前代码、配置和 `必读.md`/功能索引优先；日志只解释关键变化为何发生、改了什么、如何验证以及何时需要回看。格式和写入规则见 [change-log.md](change-log.md)。

## 功能文档模板

```markdown
# F-001 功能名

- 职责：该功能保证什么。
- 非目标：最容易被误加但当前不支持的内容。
- 入口：文件路径与关键符号。
- 文件映射：每个负责文件在本功能中的作用；不列无关文件。
- 依赖与接口：输入、输出、事件、数据结构和必须保持的不变量。
- 数据流：只有跨越多个模块时才写。
- 验证：最小测试或检查命令，以及关键可观察结果。
- 修改提示：最常见改动应从哪里开始，并需同步检查哪些共享契约。
```

## 更新规则

1. 只更新本次改动影响的功能行、公共接口和功能文档。
2. 路径、符号或命令变化时立即替换旧内容，不并列保留过期说明。
3. 不粘贴源码；使用路径、符号和短契约定位事实。
4. 同一事实只保存在一个地方：共享约束放仓库现有等价主索引（默认布局下为 `必读.md`），功能细节放对应文档。
5. 删除已失效的风险和文件映射；项目记忆描述当前状态，不承担变更日志职责。
6. 文档内容必须能从代码、配置或验证结果中核实；不记录推测性未来设计。
7. 多功能或高风险项目先保存全部规范化验收语句和明确非目标，再维护 `R- →（A- 可选）→ F- → 文件/符号 → T-` 映射；普通单功能任务不为编号而编号。
8. 外部证据优先记录官方来源、版本、获取时间、关键事实和失效条件。过期、冲突、法律/安全等易变事实在复用前重新核实；不缓存密钥、令牌、个人数据或无关网页内容。
9. 本 skill 的全局模型/MCP/成本默认值只存在于 skill；项目记忆仅记录项目特有例外，避免每个项目重复消耗上下文。
10. 修改或优化项目时，先读项目索引，再搜索 `docs/ai/changes/index*.md`；只打开与本次 `F-`、路径/符号、公共契约、数据或配置命中的日志，不顺序阅读全部历史。
11. 新项目或多功能集成在最终整体审计前更新当前状态索引，使审计能核对文件映射、公共契约和 `A-` 决定；终审修复改变这些事实时同步更新后再集中复审。重大改动历史日志仍在终审通过后写入。
12. 底层应用任务通过 `AC-0` 至 `AC-8` 后，只把会约束后续修改的 owner、权威来源、公共 contract、generation/恢复边界和发布 gate 作为 `A-` 决定落入现有主索引，并写明实现/验证位置与失效条件；完整逐轮闭包账本留在审计证据中，不复制进 `必读.md`。
