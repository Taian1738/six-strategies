# 六韬（LT）

[English](./README.en.md)

六韬是一套面向 Codex 的软件工程协作协议，用于把复杂的软件构建、修复、重构与长期维护任务，组织成可追溯、可验证、可恢复的执行闭环。

它不是某个框架，也不是一段孤立的提示词。六韬提供的是一套轻量的工作约束：先冻结目标和边界，再按风险选择架构门、实现批次、验证方式与审计深度，最后留下足够精确的项目记忆，让下一次修改只需读取真正相关的内容。

## 六韬解决什么问题

大型软件任务最容易失控的地方，不是“不会写代码”，而是需求、架构、实现、测试和历史信息彼此脱节。六韬通过统一编号和门禁把这些环节连接起来：

- 用 `R-` 记录可观察的需求和验收条件。
- 用 `A-` 记录架构、边界、不变量和关键取舍。
- 用 `F-` 划分有明确文件所有权的实现批次。
- 用 `T-` 固定测试、检查命令和可复核证据。
- 对底层架构、公共契约、权限、迁移、IPC、插件、构建和发布底座执行专门门禁。
- 对重大变更保留集成级日志，支持后续按功能、路径或契约增量维护。

## 核心工作流

```text
目标冻结 → 影响面判断 → 最小架构 → 实现批次
    → 即时验证 → 项目记忆 → 统一审计 → 交付日志
```

六韬坚持最小充分原则：优先复用现有实现、标准库和已安装能力；只有真实需要时才增加模块、接口、依赖或抽象。普通局部修改不会被自动扩大成无关的架构重构。

## SOL / Luna 分层协作

- **SOL**：负责未冻结的关键架构、公共契约、不可分关键实现和独立终审。
- **Luna**：负责事实取证、已冻结且边界清晰的实现、精确验证和机械日志工作。

Luna 只有在事实范围、产品行为、信任边界、状态时序、写集和验证命令都已明确时才执行写入；不把未决的产品或架构选择交给有界实现批次猜测。

## 安装

从 [Release 直链](https://github.com/Taian1738/six-strategies/releases/download/v2026.08.21/ltskill-20260821-142646.zip) 下载完整技能包，解压到 Codex 技能目录，并保持以下结构：

```text
<CODEX_HOME>/skills/ltskill/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
    ├── audit-routing.md
    ├── change-log.md
    ├── dispatch-contracts.md
    ├── foundation-gate.md
    ├── project-memory.md
    └── sol-cost-controls.md
```

安装后可使用 `$ltskill` 显式调用六韬。

也可以直接浏览仓库中的 [SKILL.md](./SKILL.md)、[代理配置](./agents/openai.yaml) 和 [references](./references/) 目录。

## 使用边界

六韬只规定软件任务的组织、路由、验证和维护方式，不替代项目自身的需求、测试、权限策略或发布审批。安装依赖、发布产物、修改真实环境以及其他外部状态变更，仍应遵循使用者的明确授权和项目规则。
